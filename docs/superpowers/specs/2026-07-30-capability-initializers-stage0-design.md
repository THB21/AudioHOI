# Capability Initializers and Fresh Stage 0 Design

## Goal

Remove the three remaining production blockers that prevent a new video or a configured known asset from entering the same object solver:

1. chair initialization must not read a solved or legacy object state;
2. periodic rigid initialization must not depend on mug-named seed code or fixed result paths;
3. Stage 0 must run the existing preprocessing implementations for missing required artifacts and publish typed solver inputs from a fresh result directory.

The object solver remains `GenericSequenceExecutor`. GVHMR remains a read-only source of skeleton sites and camera information. This work does not optimize human state, publish human results, invoke human refinement, change losses or thresholds, or add test files.

## Non-goals

- No chair, mug, suitcase, or ping-pong optimizer.
- No learned replacement for SAM2, CoTracker, DA3, GVHMR, or the audio detector.
- No automatic asset creation or open-world geometry recovery.
- No continuous weights or pose values generated by VLM/LLM.
- No promotion of an output that has not been decoded into object and skeleton-plus-object renders.

## Chosen architecture

Production dispatch is based only on declared capabilities:

```text
asset descriptor + typed measurements + typed contacts
                         |
                         v
              StateContractFactory
                         |
                         v
          CapabilityInitializerRegistry
        point_depth / line_correspondence /
      periodic_rigid / articulated_correspondence
                         |
                         v
                 initial states
                         |
                         v
          one SequenceProblemFactory
                         |
                         v
          one GenericSequenceExecutor
                         |
                         v
       one AcceptedObjectOutputPublisher
```

`case_name` remains an opaque sample/provenance identifier. It cannot select a state schema, initializer, geometry provider, factor, or solver.

## Subproject A: descriptor-driven state contracts

### Asset schema

`scripts/shared/generic_contact_pipeline/configs/assets/chair_articulated.json` and `mug_periodic_rigid.json` gain an explicit `state_contract` and `initializer` section.

The chair descriptor declares:

- root translation and quaternion rotation;
- articulated joint names, source fields, URDF joint mapping, bounds source, and descriptor defaults;
- semantic line/point features used for correspondence;
- contact features and support features;
- initializer kind `articulated_correspondence`;
- minimum correspondence requirements and the finite hypothesis set.

The mug descriptor declares:

- root translation, quaternion rotation, scale, and one periodic phase DOF;
- phase axis, origin, wrapped bounds, and periodic feature mapping;
- initializer kind `periodic_rigid_observation`;
- typed observation roles for body center/depth/orientation and handle phase;
- the permitted missing-observation policy: interpolate between observed frames, then hold the nearest observed phase at sequence boundaries. It may not load a solved pose.

### Factory boundary

Create `core/state/asset_state_contract.py` to parse these declarations into `StateSpec`, `GeometryDescriptor`, and provider construction inputs. It validates that declared feature IDs exist in the asset descriptor and that state indices are derived from DOF IDs rather than fixed numeric offsets.

`core/solver/capability_production_problem.py` calls this factory for every geometry family. It no longer constructs a rigid-mesh state specifically in `_state_spec()`, and it no longer returns `prepare_legacy_articulated_object_problem()` for `legacy_state_artifact`.

Failure is explicit when a descriptor is incomplete, a URDF joint is absent, a typed feature has no asset mapping, or no valid initialization hypothesis can be formed.

## Subproject B: generic observation-derived initializers

Create `core/solver/capability_initializers.py` with one input/output contract:

```python
InitializationRequest(
    state_spec,
    geometry_provider,
    measurements,
    contact_constraints,
    human_sites,
    cameras,
    descriptor_initializer,
)

InitializationResult(
    states_by_frame,
    template_rows,
    hypothesis_ledger,
    input_artifact_ids,
)
```

### Articulated correspondence

The generic articulated initializer:

1. initializes joints from descriptor defaults or observation-derived joint measurements;
2. collects visible typed line/point measurements by semantic feature ID;
3. forms root-pose hypotheses using asset-local feature geometry, pinhole camera rays, available metric depth, read-only GVHMR contact sites, and explicit support plane evidence;
4. ranks the finite hypotheses by reprojection, contact, bounds, and support residuals using the same factor evaluators used later by the solver;
5. interpolates missing frames and records every selected or rejected hypothesis.

It does not read `object_pose_init.csv`, `object_pose.csv`, baseline paths, chair solver output, or a contact-chord solved pose. The chair case config changes from `legacy_state_artifact` to `articulated_correspondence` and lists only observation/contact/environment artifacts.

### Periodic rigid observation

The periodic initializer consumes typed measurements selected by descriptor roles. Body translation/depth/orientation and periodic phase are assembled through DOF IDs. Wrapped interpolation handles phase continuity. Generic `PeriodicFeatureRule` maps phase to asset features.

The initializer does not read fixed paths such as `observation_seed/body_pose.csv` or `observation_seed/axial_phase.csv`. A temporary adapter may convert those files into typed MeasurementIR for parity, but the initializer sees only typed measurements and provenance IDs. The accepted path must not import `components/pose/solvers/mug_observation_seed.py` or `projected_periodic_sequence.py`.

## Subproject C: fresh Stage 0 artifact runner registry

Create `core/preprocess/types.py`, `registry.py`, `runtime.py`, and `publish.py`.

Each `PreprocessTaskSpec` declares:

- task ID and capability role;
- runtime environment key from `runtime_envs.yaml`;
- input and output artifact roles;
- command builder;
- required/optional status;
- cache hash inputs;
- output validator.

Register only the existing required tasks:

1. frame/audio extraction from `video.mp4`;
2. SAM2 masks and trajectory;
3. CoTracker points and center track;
4. DA3 scene depth through a repository-owned wrapper around `depth_anything_3.api.DepthAnything3.inference` in the configured `da3` environment;
5. GVHMR through `scripts/shared/human/gvhmr/run_gvhmr_local.py` in the configured `gvhmr` environment;
6. audio event extraction through `src.audio` followed by an adapter that publishes `results/events/audio_events.csv` as `AudioEventIR`-compatible rows;
7. typed measurement, contact, audio, and interaction-state publication into the selected result directory.

The registry resolves a DAG from artifact roles, reuses an output only when its manifest input hashes match, and runs missing dependencies in topological order. Every subprocess uses the Python executable selected by `runtime_envs.yaml`, not the current shell.

Stage 0 fails on the exact task when a required model, executable, input, or output contract is missing. It never silently copies an artifact from another case. Ablation-disabled audio produces an explicit disabled artifact record rather than a fake missing error.

`stages/main/stage0_preprocess.py` becomes a thin orchestrator over this registry and writes one manifest containing task attempts, commands, runtime Python paths, model/input/output hashes, cache decisions, and validation results.

## Typed publication boundary

After preprocessing, legacy CSV formats may exist for compatibility, but production problem preparation resolves roles from the Stage 0 manifest and consumes:

- `measurements.jsonl`;
- `contact_constraints.jsonl`;
- `audio_events.jsonl`;
- `interaction_timeline.jsonl`;
- calibrated camera/environment descriptors;
- read-only GVHMR site measurements.

Legacy adapters are allowed only before this boundary. They cannot branch on chair or mug inside `core/solver`, `core/state`, or production `core/factors`.

## Error handling and provenance

- Missing required task output: stop and identify task ID, environment, command, and missing artifact role.
- Invalid descriptor: stop before solver construction with descriptor path and offending field.
- Insufficient initialization evidence: publish a blocked hypothesis ledger; do not fall back to historical pose.
- VLM `unclear`: retain both finite hypotheses or downweight predefined factor tiers; do not manufacture a pose.
- Solver or publication gate failure: retain isolated attempt, metrics, render evidence, and automatic blocking reasons.

All provenance uses content hashes. Absolute environment paths may be recorded diagnostically, but canonical hashes use repository-relative artifact identities and content.

## Verification strategy

Per user instruction, add no test files. Verification uses existing checks plus direct production smokes:

1. `py_compile` for every modified Python module;
2. config/descriptor parse and capability-resolution smoke for all five canonical assets;
3. core scan proving no production `profile.case_name == "chair"` or `== "mug"` remains;
4. chair preparation from a temporary result directory that contains only copied observation/contact/environment inputs, with no `object_pose*.csv`;
5. mug preparation from typed measurements after temporarily hiding the two fixed `observation_seed` files;
6. Stage 0 DAG dry-run showing exact reuse/run decisions for all registered artifact roles;
7. one fresh-directory Stage 0 execution using the available environments, followed by typed IR validation;
8. isolated chair and mug solves through `GenericSequenceExecutor`, hard metrics, object render, and read-only GVHMR skeleton-plus-object render;
9. `git diff --check` for code/config/docs and explicit CSV schema/hash checks for generated data.

## Exit criteria

This design is complete only when:

- chair preparation reports `initializer_kind=articulated_correspondence`, `baseline_pose_read=false`, and does not open any object pose seed;
- mug preparation reports a descriptor-selected periodic initializer and succeeds without fixed observation-seed paths;
- both use `GenericSequenceExecutor`, `case_dispatch_used=false`, and `human_state_optimized=false`;
- Stage 0 can materialize every required artifact role from `video.mp4`, asset/profile configuration, installed models, and registered environments in a fresh result directory;
- solver inputs are selected by typed artifact role and asset capability;
- no loss, threshold, or solver algorithm is changed;
- no human code is modified except invoking the existing GVHMR runner as a read-only preprocessing dependency;
- chair and mug full-video render evidence is produced before any canonical promotion.

## Implementation sequence

The work is split into three separately reviewable commits/plans:

1. descriptor-driven StateSpec and chair articulated initializer;
2. descriptor-driven periodic rigid initializer and mug migration;
3. Stage 0 registry, DA3/GVHMR/audio runners, and typed publication.

Each step must leave the existing five-case pipeline runnable and must not introduce a compatibility dispatcher into the generic solver.
