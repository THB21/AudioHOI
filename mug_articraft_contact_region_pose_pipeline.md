# Mug + Articraft Contact Region / Pose Fitting Pipeline

## 0. Current Goal / 当前目标

This document describes the current experimental mug pipeline. The goal is not to detect the mug handle independently in every frame. The goal is:

```text
Articraft canonical mug proxy
+ object-side contact region
+ keyframe rim/bottom/body pose observations
+ propagated mug pose during contact interval
+ final contact-aware optimization input
```

中文：当前目标不是逐帧找把手，而是把 Articraft 生成的 canonical mug proxy 接到视频中的 mug 上，得到稳定的杯体 6D pose、handle/contact region 的 object-local 位置，并服务后续 contact residual。

---

## 1. Important Separation / 必须分开的三个量

### 1.1 Rim / bottom annotation

`rim/bottom` annotation is used to fit the visible mug body pose.

It constrains:

```text
mug body position
mug body orientation
rim ellipse projection
bottom ellipse projection
body axis projection
```

It should not be determined by `handle_visible`.

中文：`rim/bottom` 标注只负责杯体刚体位姿，不应该被 handle 是否可见决定。

### 1.2 Handle visibility

`handle_visible` only means whether the handle should be drawn or allowed to appear outside the body silhouette.

It controls:

```text
render handle or not
occlusion constraint for hidden handle
```

It must not change rim/bottom annotation.

中文：`handle_visible` 只控制把手是否画出来、隐藏帧里把手不能露到杯体外面。它不能反过来影响杯口/杯底标注。

### 1.3 Object-side contact region

The handle/contact region is a fixed semantic region on the canonical mug proxy. Once the mug 6D pose is known, the 2D contact point should be projected from the canonical mug pose.

中文：object-side contact region 应该固定在 Articraft mug 的局部坐标里，跟着 mug body pose 走，而不是逐帧重新猜一个 handle 点。

## 6. Propagation From Manual Frames / 从人工帧推理其它帧

Current propagation logic:

```text
exact manual frame exists
  -> use exact manual rim/bottom
else if between manual frames
  -> propagate/interpolate rim/bottom relative to body center
else
  -> nearest manual relative geometry + body-center translation
```

Generated file:

```text
samples_known_object/02_mug/annotations/mug_rim_bottom_propagated_from_manual.json
```

This is used by M3 fitting before segmentation mask fallback.

中文：如果某帧没有人工标注，会从相邻人工帧推理 rim/bottom。推理不是最终真值，只是比 mask/bbox 更稳的约束。

## 7. Human / Object Motion Gate / 人手与物体运动门控

Problem observed:

```text
During frames 69-87, human hand/object center move only slightly,
but naive interpolation from 67 to 90 rotates the mug too much.
```

Current gate:

```text
if contact side unchanged
and object center displacement is small
then freeze relative rim/bottom structure from the previous reliable manual frame
and only translate it with object center
```

Current source label:

```text
motion_gated_hold_manual_67_before_90
```

Example checked frames:

```text
69, 75, 80, 86, 87
```

中文：这一步试图利用“人手幅度小、物体中心幅度小”的事实，避免杯子在遮挡段里无缘无故大旋转。

Current limitation:

```text
This gate only constrains 2D rim/bottom annotation propagation.
It is not a real 3D hand-object rigid tracking model.
```

中文：它只是 2D 标注传播门控，不是真正的 3D 刚体追踪。

## 10. Why The Current Result Still Looks Bad / 为什么现在效果仍然不好

### 10.1 The middle pickup/drinking interval is not truly tracked

The key failure:

```text
The middle mug pickup/drinking segment cannot be reliably tracked by the current 2D propagation-only method.
```

中文：中间拿起水杯/喝水段目前无法靠这套 2D propagated annotation 稳定追踪。

Reasons:

```text
1. The mug body is close to a textureless cylinder.
2. The handle is often occluded by the hand or hidden behind the body.
3. Visible rim/bottom arcs are incomplete and change under perspective.
4. 2D bbox/body-center motion is small, but 3D rotation can still change.
5. Conversely, if 2D motion is small, naive 2D interpolation may invent fake rotation.
6. The current system does not have real per-frame 6D pose tracking.
7. It does not use a physical hand-object rigid attachment constraint in 3D.
8. It does not fit the Articraft mesh silhouette against the full visible mug mask.
```

中文总结：

```text
中间段最大问题不是某一个 loss 权重，而是观测本身不够。
杯子是圆柱体，把手被挡，杯口/杯底只露一部分。
现在只是用人工标注和 2D 传播去猜 3D 姿态，缺少真正的 6D pose tracking。
```

### 10.2 30/40/50 and 69-87 expose different failures

```text
30/40/50:
  propagation from early manual frames is not reliable.
  The mug is transitioning into drinking pose, and sparse annotations are insufficient.

69-87:
  naive interpolation over-rotates.
  Motion gate reduces fake rotation, but it can also freeze a wrong relative pose if the anchor itself is not sufficient.
```

中文：30/40/50 是早期过渡段标注不足；69-87 是遮挡稳定段，线性插值会乱转，motion gate 能压住但不等于真实 3D 追踪。

## 12. What Is Missing / 下一步真正缺什么

To make this physically consistent, the next step should not be more ad-hoc handle visibility rules. It should add real 6D mug pose tracking:

```text
1. Add more precise manual rim/bottom/silhouette annotations for transition frames.
2. Fit the full Articraft mug mesh silhouette to the visible mug mask.
3. Use a temporal 6D pose optimizer over the whole contact interval.
4. Add a hand-object rigid attachment term during grasp.
5. Keep handle/contact region fixed in object-local coordinates.
6. Use hidden-handle constraints only as visibility/occlusion constraints, not as pose drivers.
```

中文：下一步不是继续堆 handle visible 规则，而是把 Articraft mug 当成一个刚体，做整段 6D pose tracking。手接触期间，杯子和手的相对 attachment 应该稳定，handle/contact region 固定在物体局部坐标里。

## 13. Practical Current Conclusion / 当前结论

Current pipeline can do:

```text
manual keyframe rim/bottom fitting
review image generation
propagation from reliable manual frames
motion-gated propagation for small-motion stable holding segments
basic Articraft mug overlay
```

Current pipeline cannot yet do reliably:

```text
fully automatic mug 6D tracking through pickup/drinking/putdown
stable hidden-handle pose recovery
physically correct handle-side rotation under heavy occlusion
robust contact-region projection during the middle drinking interval
```

中文一句话：

```text
现在这条线已经证明了 Articraft mug + rim/bottom keyframe fitting 可以接入，
但中间拿起水杯的遮挡段无法靠当前 2D propagation 稳定追踪，
必须升级到真正的 temporal 6D pose fitting / hand-object rigid attachment。
```

## 15. Is The Previous Radius-Free Pipeline Abandoned? / 之前 radius-free 是否完全不用？

No. The previous radius-free pipeline is not abandoned.

It is still used for:

```text
1. SAM2 / object mask
2. object_observations.csv
3. object_proxy_observations.csv
4. DA3 depth prior / object_depth_smooth
5. contact intervals and candidates
6. active human part proxy: active_part_u / active_part_v / active_part_z
7. contact timing and human-side contact part
8. initial pose / depth / center priors
```

What is being replaced is only the mug-specific pose propagation/fitting stage:

```text
Old mug path:
  sparse keyframe M3
  + 2D rim/bottom propagation
  + framewise render/interpolation

New mug direction:
  radius-free observations as input
  + Articraft canonical mug proxy
  + temporal 6D pose optimization
  + hand/object attachment residual
```

中文：之前 radius-free 不是废掉。它仍然是观测层和 contact/candidate 层。现在要替换的是 mug 这种非球体对象的姿态求解层：不再只靠 2D propagated annotation，而是把这些 radius-free 观测作为 temporal 6D optimizer 的输入。

Practical dependency:

```text
radius-free stage0/stage1/stage2 outputs
  -> provide observations and contact windows
M4 temporal 6D mug fitting
  -> consumes those observations
  -> outputs better object pose for later contact refinement
```

中文一句话：

```text
radius-free 负责“看到了什么、什么时候接触、参考点在哪里”；
Articraft + temporal 6D 负责“这个 mug 作为刚体到底怎么转”。
```

## 7. Body-Only Cylinder Debug / 只看杯身的圆柱调试

The current failure is not only a handle/contact-region problem. The mug body itself can become unstable when the cup slightly rotates and the bottom becomes visible.

当前失败不只是把手问题。杯身轻微旋转、杯底露出时，杯身本体也会贴不稳。

A key issue in the older Articraft overlay path is that the proxy body was not treated as a true circular cylinder:

```text
BODY_R = 0.040
BODY_D = 0.014
```

This makes the mug body geometrically flattened in depth. Once the pose rotates, the projected body can look twisted even before the handle is considered.

中文：旧的 overlay 里杯身深度半径比横向半径小很多，相当于把圆柱压扁了。这样一旋转，杯身投影会像被拧过，不看 handle 也会错。

For debugging, a separate body-only fitter was added:

```text
scripts/shared/radius_free_proxy/stage1_observation/fit_mug_body_only_cylinder_pose.py
```

It uses:

```text
true circular cylinder body: BODY_D = BODY_R
rim ellipse / bottom ellipse observations
body bbox and body center
DA3 / object depth prior
temporal smoothness
no handle
no contact region
```

Outputs:

## M9 Fix: Visual Handle vs. Hand Contact Region

### M10 Rigid Temporal Handle-Phase Inference

The visual handle phase is now optimized as a hidden rigid degree of freedom over the whole frame sequence. Visible-handle detections are sparse observations; hidden frames do not update the handle directly. The optimizer uses:

- robust visible-handle phase residuals, weighted by confidence and reprojection error;
- first-order angular velocity smoothness;
- second-order angular acceleration smoothness through occlusion;
- weak interpolation prior only to stabilize fully unobserved ends;
- isolated phase-alias rejection, e.g. a single-frame phase flip inside a consistent visible segment.

This is still an axial-phase diagnostic on top of the M5 body pose, not a full joint optimization of body pose + handle phase + hand attachment.

### Hidden Handle as Negative Observation

Hidden frames are now used as negative visibility evidence, not ignored. For frames marked `handle_visibility_policy=hidden`, the visual handle is not used as a positive detector anchor. Instead, the phase optimizer adds a penalty when the projected Articraft handle protrudes outside the observed mug body silhouette. This encourages the inferred rigid handle phase to place the handle behind the cup/body/hand occlusion.

- `overlay_visible.mp4` hides the handle in hidden frames.
- In both modes, hidden frames still influence the optimized phase through the negative-visibility residual.

### F. Confirmed Handle Contact Point Selection / confirmed 把手接触点定位

The previous M13 implementation still used the propagated object-side `contact_u/contact_v` as the point location, then only classified whether it was near the Articraft handle. This was wrong for confirmed hand-handle contact: the point could sit on the mug body or an arbitrary propagated contact region instead of the actual hand-touching handle area.

Current fix:

```text
if VLM / explicit evidence confirms hand-handle contact:
  project the Articraft `handle_loop` mesh with the current mug pose
  find the projected handle mesh vertex closest to the active GVHMR hand proxy in image space
  use that handle mesh point as contact_u/contact_v/contact depth/local point
else:
  do not create a direct hand-handle anchor from nearest geometry alone
```

中文：之前只是“旧 contact 点离 handle 最近”，不是“手接触 handle 的具体点”。现在 confirmed handle contact 会在 Articraft handle mesh 投影上找离当前手位置最近的点，作为真正的 hand-handle contact candidate。

New CSV/debug field:

```text
handle_contact_selection = articraft_handle_mesh_nearest_active_hand
```

Interpretation:

```text
nearest_articraft_part == handle_loop
  is only a geometric label.

handle_contact_selection == articraft_handle_mesh_nearest_active_hand
  means the contact point was actively re-selected from the handle mesh using the current hand location.
```

Remaining limitation:

```text
The selection currently uses the active GVHMR hand proxy projection, not dense MANO/HaMeR hand surface vertices.
The 3D hand/object depth gap is still exported as an alignment residual, not used to reject visual contact.
```

中文限制：现在是用 GVHMR active hand proxy 的图像位置去 handle mesh 上选最近点，还不是完整手 mesh 到 handle mesh 的表面接触。深度差仍然作为后续优化要解决的对齐项。


### G. Handle Contact Point Misalignment Gate / 把手接触点贴手门控

Even when VLM confirms `hand_contact_part=handle`, the projected Articraft handle mesh can still be wrong if the current mug/handle pose is misaligned. In that case, picking the nearest handle vertex can place the contact circle on the mug body instead of the real hand-handle interface.

Current guard:

```text
if confirmed handle contact
and projected handle point is more than 25 px from the active hand proxy:
  object_contact_event = handle_contact_point_misaligned
  hand_mug_contact_state = confirmed_handle_but_projected_point_not_on_hand
  use_this_point_for_hand_attachment = 0
  use_previous_grasp_for_hand_attachment = 1
```

中文：VLM 说 handle contact 不代表当前投影的 Articraft handle 点就一定对。如果投影 handle 点离手太远，就说明 mug/handle pose 还没对上。这个错误点不能画成 confirmed contact，也不能喂给 attachment；应该先用它提示后续要优化 handle/mug pose。

### J. Stable Grasp Anchor Rules in M14 / M14 稳定抓握锚点规则

M14 now explicitly separates contact classification from grasp-anchor updates.

Rules implemented:

```text

  stable_grasp_local = current object-local handle contact point

```

Segmented optimization detail:

```text

This prevents segment boundaries from resetting the grasp anchor.
```

中文说明：M14 不再用 VLM 的 `handle_contact=True` 直接新建抓握点。只有 contact CSV 里 `use_this_point_for_hand_attachment=1` 的 confirmed handle contact 帧能更新 object-local grasp anchor。喝水 rim、hidden、occluded、misaligned frame 都只能沿用已有 stable grasp，不能从画面上重新找 body/rim/unknown 点覆盖它。


### K. Visibility Transition Alpha / 可见性过渡权重

The VLM output is not used as a hard binary switch anymore for M14 handle-phase optimization.
A visible/hidden label is first converted into a continuous `visibility_alpha` track:

```text
hidden = 0
visible = 1
visible -> hidden boundary: alpha ramps down
hidden -> visible boundary: alpha ramps up
short visible/hidden islands are filtered before alpha is computed
```

This is necessary because a rigid mug handle cannot instantly appear or disappear.
At transitions such as frames 89-97, the handle should emerge from occlusion, become partially/fully visible, and then disappear again. The phase optimizer therefore treats these frames as a continuous process, not independent VLM decisions.

Current implementation:

```text
scripts/shared/radius_free_proxy/stage1_observation/render_mug_articraft_joint_contact_phase.py
  filter_vlm_short_visible_islands()
  compute_visibility_alpha()
```

How it is used:

```text
visible handle residual weight *= visibility_alpha
hidden handle negative-visibility residual weight *= (1 - visibility_alpha)
render writes visibility_alpha to handle_phase_joint_contact.csv
```

The updated M14 render is now generated with full-sequence optimization rather than independent segments, so the mug axial phase is continuous across the whole video:

```text
samples_known_object/02_mug/results/renders/M14_joint_contact_handle_phase/overlay.mp4
samples_known_object/02_mug/results/renders/M14_joint_contact_handle_phase/handle_phase_joint_contact.csv
```

For the 89-97 transition, the current alpha track is intentionally low at the beginning/end and high in the middle, representing a handle that briefly emerges and then goes back into occlusion.

中文说明：现在 M14 不再把 VLM 的 `visible/hidden` 当作硬开关。先把它变成连续的 `visibility_alpha`：可见段边界逐渐升高/降低，hidden 段边界也只是减弱 hidden penalty，而不是突然把 handle 拉到可见侧。这样 89-97 这类片段会被解释成“把手短暂冒出来又回去”的刚体连续过程，而不是 89 帧突然完全出现、98 帧突然完全消失。

同时，M14 现在使用整段 full-sequence phase optimization 输出当前结果，避免之前分段优化在 100/101 之类边界产生 phase 断层。

## 15. Current Hand-Handle Contact Logic / 当前手-把手接触逻辑

### 15.1 The key correction / 关键修正

The mug interaction is a continuous grasp interval. A hidden handle frame does **not** mean no hand-object contact. It means the hand-handle contact region is occluded by the mug body, the hand, or the camera viewpoint.

中文：这段 mug interaction 本质是持续抓握。`hidden` 不是没有接触，而是手和把手的接触点在画面里被杯体/手/视角遮住了。

Therefore the current rule is:

```text
visible confirmed hand-handle frame
  -> allowed to initialize/update the stable object-local grasp anchor

hidden / occluded / depth-misaligned frame
  -> must keep the previous stable grasp anchor
  -> still contributes a hand-object attachment residual
  -> must not detect a new rim/body/unknown point as hand contact

rim drinking frame
  -> rim/mouth contact may be visible
  -> hand-handle grasp still continues
  -> rim must not overwrite the stable hand-handle anchor
```

中文规则：

```text
清楚可见的手-把手帧
  -> 可以初始化/更新 stable object-local grasp anchor

不可见/遮挡/深度不准帧
  -> 只能沿用之前的 stable grasp anchor
  -> 仍然是持续抓握约束
  -> 不能重新从画面上找 body/rim/unknown 点当作手接触点

喝水杯沿帧
  -> 可以有嘴-杯沿 contact
  -> 但手-把手抓握仍然持续
  -> rim contact 不能覆盖 hand-handle anchor
```
